# Optium+ File Manager

**Optium+ File Manager is a Windows desktop app that sorts files by their contents, reads supported images and documents, and helps find files with natural-language search. Local analysis works offline; cloud AI is optional.**

[![GitHub stars](https://img.shields.io/github/stars/kokkanisstr-tech/Optium-Plus-File-Manager?style=social)](https://github.com/kokkanisstr-tech/Optium-Plus-File-Manager)

If Optium+ File Manager is useful to you, please give it a star.

---

Windows-приложение для локальной сортировки файлов по содержимому, а не только по расширению. Входящие файлы проверяются, получают SHA-256, классифицируются локально, а неоднозначные результаты остаются в очереди ручной проверки. История хранится в SQLite; перемещение можно отменить.

## Быстрый запуск

Для сборки нужен .NET 10 SDK и Windows. Самостоятельный x64-пакет не требует отдельно установленного .NET Runtime:

```powershell
dotnet restore
dotnet publish OptiumPlusFileManager.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:IncludeAllContentForSelfExtract=true -o publish/win-x64
```

Запустите `publish/win-x64/OptiumPlusFileManager.exe`. Приложение автоматически запускает локальный API на `http://127.0.0.1:37582`; его можно выключить на вкладке **API и MCP**. Автосортировка входящих папок по умолчанию выключена. Для встроенного OCR требуется Microsoft Visual C++ 2015–2022 Redistributable x64; без него сортировка остаётся доступна, а недоступный OCR оставит файл для проверки.

## Как пользоваться

1. На вкладке **Настройки** добавьте одну или несколько входящих папок. Можно включить вложенные папки, задать исключённые пути и маски имён, а также автозапуск Windows.
2. Нажмите **Сортировать сейчас** для уже имеющихся файлов или включите автоматическую сортировку.
3. Приложение определит формат по сигнатуре содержимого, проверит стабильность записи и SHA-256, извлечёт доступный текст и применит локальную классификацию.
4. Уверенные результаты попадут в `OptiumPlusFileManagerData/Sorted`. Неоднозначные файлы останутся на вкладке **На проверку**. После подтверждения можно по желанию сохранить правило для файлов с таким же точным именем.
5. На вкладке **Обзор** крупные ярлыки ведут прямо к папкам C#, Python, SQL, документов, изображений, архивов и ко всем результатам. В дереве ниже видны категории, подкатегории и файлы; папки и файлы различаются значками, а двойной щелчок открывает их в Проводнике.
6. На вкладке **История** доступны фильтры по времени, категории, статусу и источнику, повторный анализ, отмена перемещения и экспорт CSV.
7. На вкладке **ИИ-поиск** опишите нужный файл обычными словами. Запрос вроде «математический модуль на C#» сначала проверяет `Programming/CSharp`; если совпадений нет, поиск проверяет остальные папки в `Sorted`. Если файл нигде не найден, приложение сообщает об этом.
8. В правом верхнем углу включается **Тёмная тема**. Выбор сохраняется и применяется ко всем вкладкам при следующем запуске.

Перетаскивание или ручное добавление файла создаёт копию в шлюзе приложения; исходный файл на выбранном месте остаётся. Отмена такой операции возвращает копию в шлюз `Inbox`. Файлы из наблюдаемых папок перемещаются, а отмена возвращает их к исходному пути.

Подробные шаги и расшифровка статусов приведены в [руководстве пользователя](docs/USER_GUIDE.md).

## Категории и правила решения

Категории задаются фиксированным справочником в `Domain/CategoryCatalog.cs`: программирование (C#, Python, Java, JavaScript/TypeScript, SQL, C, C++, HTML, CSS и другой код), документы (учёба, работа, финансы, прочее), изображения (фото, скриншоты, сканы, схемы, иллюстрации и прочее), аудио, видео, архивы, приложения и прочее. Каталог создаётся по мере появления файлов; имена папок ограничены справочником и проверяются до перемещения.

| Уверенность | Решение |
|---|---|
| `0.85` и выше | перемещение в категорию |
| от `0.60` до `0.85` | ручная проверка |
| ниже `0.60` | `Review/Unknown` |

Неверное расширение и опасная ZIP-структура не считаются обычным результатом классификации. Архивы ZIP до 256 МБ проверяются на пути `..`, число элементов, суммарный распакованный размер и коэффициент сжатия; архивы других форматов не распаковываются. Программа не запускает принятые файлы.

## Локальные данные

| Что | Где |
|---|---|
| Настройки | `%LOCALAPPDATA%\OptiumPlusFileManager\settings.json` |
| SQLite, блокировки, журналы | `%LOCALAPPDATA%\OptiumPlusFileManager\.data` |
| Шлюз загрузок | `%LOCALAPPDATA%\OptiumPlusFileManager\Inbox` |
| Очередь проверки, карантин и ошибки | `%LOCALAPPDATA%\OptiumPlusFileManager\Review`, `Quarantine`, `Errors` |
| Отсортированные файлы | `Рабочий стол\OptiumPlusFileManagerData\Sorted` |

При переименовании приложение продолжает использовать найденный профиль предыдущей версии: `%LOCALAPPDATA%\Optium`, `%LOCALAPPDATA%\OY_files` или `%LOCALAPPDATA%\FileSorterCollege`. Для папки результатов также поддерживаются прежние `Рабочий стол\OptiumData\Sorted`, `Рабочий стол\OY_filesData\Sorted` и `Рабочий стол\FileSorterData\Sorted`. Настройки и отсортированные файлы остаются на месте; сохранённый в настройках путь остаётся главным.

Журнал событий в SQLite хранит историю операций. Дополнительный JSONL-журнал не содержит извлечённый текст, API-ключи или полные пути. При недоступности этого дополнительного журнала обработка продолжается.

## Поддержка форматов

- По сигнатурам: PDF, изображения, ZIP/OpenXML, RAR, 7z, gzip, tar, OLE, EXE/DLL, MP4, MKV, AVI, WAV, MP3, OGG и FLAC.
- DOCX, XLSX и PPTX: ограниченное извлечение текста из XML-контейнера. PDF: текст до первых 40 страниц; страницы без текстового слоя передаются в локальный OCR.
- Текст и исходный код: чтение ограничено 250 000 символами. Для локального определения используются синтаксические признаки C#, Python, Java, JavaScript/TypeScript, SQL и HTML.
- ZIP: анализируется безопасный список имён, без распаковки вложений.
- Для PNG/JPEG/GIF/WebP/BMP/TIFF/ICO читаются размеры из ограниченного заголовка и локально распознаётся текст встроенным OCR с языками `eng+rus`; изображения больше 32 МБ или 12 мегапикселей пропускаются. При необходимости можно подменить движок внешним локальным `tesseract.exe` через `FILE_SORTER_TESSERACT` и задать его языки через `FILE_SORTER_OCR_LANGUAGES`. HEIF/AVIF сохраняются для ручной проверки без OCR. WAV/MP3/FLAC/MP4/M4A/AVI получают доступные аудио/видео поля; PE-файлы — только сведения о версии/продукте. Исходники не запускаются, EXIF/GPS и доверие к подписи не извлекаются.

Встроенный OCR работает без сети. Для PDF он обрабатывает до 10 страниц без текстового слоя среди первых 40 страниц; очень большие документы остаются для проверки. Для работы OCR нужен [Microsoft Visual C++ 2015–2022 Redistributable x64](https://aka.ms/vs/17/release/vc_redist.x64.exe). OpenDocument-текст, расшифровка аудио/видео и глубокий анализ архивов не реализованы. Для некоторых контейнеров доступен только ограниченный набор технических полей. Такие случаи не маскируются как полностью распознанные и могут потребовать ручной проверки.

## Облачный анализ

Режим по умолчанию — **Off**. Ключи не сохраняются в настройках, базе, запросах интерфейса или журнале. Их нужно передать через переменные окружения текущего пользователя:

- OpenAI: `OPENAI_API_KEY`
- Gemini: `GEMINI_API_KEY`
- Claude: `ANTHROPIC_API_KEY`

По умолчанию используются модели `gpt-5.6-terra`, `gemini-3.6-flash` и `claude-sonnet-5-5`; названия можно изменить на вкладке **Настройки**. Режим `Auto` обращается к настроенным провайдерам по очереди. `Compare` запрашивает два настроенных провайдера; их разногласие или сбой одного из них отправляет файл на ручную проверку. В настройках можно установить месячный лимит запросов; `Compare` учитывает оба вызова.

В **Форматы и приватные папки…** задаются разрешённые форматы и локальные подпапки. По умолчанию разрешены текст/код, PDF и Office Open XML; остальные типы можно включить отдельно. Для визуального анализа PNG/JPEG/WebP нужно отдельно поставить галочку разрешения отправки оригинального изображения и разрешить эти типы в списке форматов. Размер изображения ограничен 12 МБ. Без этого разрешения в облако не попадут байты изображения; локальный OCR и сортировка продолжат работать. Полные локальные пути не загружаются. Вероятные приватные ключи, токены и пароли блокируют облачный анализ. Месячный лимит учитывает число запросов и не оценивает денежную стоимость; тарифы и доступность зависят от аккаунта провайдера. Индикатор **Ключ настроен; сеть не проверена** не является проверкой реального соединения.

Вкладка **ИИ-поиск** использует локально извлечённый текст и OCR для проверки файлов в `Sorted`. На холодном поиске документы читаются пакетами с ограниченным параллелизмом; извлечённый текст и поисковые термины повторно используются из ограниченного кэша приложения, пока файл не изменился. Если облачный режим включён, ИИ рассматривает все разрешённые файлы порциями до 16 кандидатов и останавливается после найденного совпадения или достижения месячного лимита. Передача подчиняется allowlist, фильтру секретов и приватным папкам, включая файлы, ранее перемещённые из приватной папки. Для визуального поиска отправка байтов PNG/JPEG/WebP требует отдельного разрешения и разрешённого типа; в один запрос включается не более двух изображений. Полный локальный путь не передаётся. При режиме `Off`, отсутствии ключа, превышении лимита или ошибке провайдера остаётся локальный поиск.

См. [сравнение локального и ИИ-анализа](docs/CLASSIFICATION.md).

Текущие модели, payload адаптеров и официальные ссылки собраны в [справочнике провайдеров](docs/AI_PROVIDERS.md). Лицензии OCR и PDF-компонентов приведены в [сторонних уведомлениях](third_party/THIRD_PARTY_NOTICES.md).

## REST API и MCP

Локальный HTTP API слушает только loopback. Read-токен даёт чтение, write-токен — изменение файлов. Токены создаются заново при запуске, если для них не заданы `FILE_SORTER_API_READ_TOKEN` и `FILE_SORTER_API_WRITE_TOKEN`; их можно скопировать на вкладке **API и MCP**. Одноразовые upload-ссылки действуют 15 минут, download-ссылки — 5 минут.

MCP доступен двумя способами:

- локальный процесс через `OptiumPlusFileManager.exe --mcp-stdio`;
- Streamable HTTP по `/mcp`, который требует авторизации.

Список REST-маршрутов, scopes и пример конфигурации для Antigravity приведены в [справочнике API/MCP](docs/API_MCP.md).

## Сборка и структура

```powershell
dotnet restore OptiumPlusFileManager.sln
dotnet build OptiumPlusFileManager.sln -c Release
dotnet publish OptiumPlusFileManager.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:IncludeAllContentForSelfExtract=true -o publish/win-x64
dotnet test OptiumPlusFileManager.sln -c Release
```

Чтобы пересобрать `OptiumPlusFileManager-source.zip`, выполните `powershell -ExecutionPolicy Bypass -File .\PackageSourceArchive.ps1`.

Для изолированного запуска можно задать `FILE_SORTER_DATA_ROOT` и `FILE_SORTER_SORTED_ROOT`. Без этих переменных приложение использует стандартные `%LOCALAPPDATA%` и папку рабочего стола.

Решение разделено на отдельные проекты: `Domain` (модели и категории), `Application` (контракты и настройки), `Infrastructure` (SQLite, безопасность, извлечение, поиск и ИИ-адаптеры), `Worker` (конвейер и наблюдение), `Api` (REST/MCP) и WinForms-проект `OptiumPlusFileManager.Desktop`. В `tests` находятся отдельные проекты unit- и интеграционных проверок. Архитектура и схема базы описаны в [технической документации](docs/ARCHITECTURE.md).
