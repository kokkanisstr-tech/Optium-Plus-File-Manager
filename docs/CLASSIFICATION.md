# Локальная и ИИ-классификация

## Сравнение подходов

| Критерий | Локальная классификация | Облачный ИИ |
|---|---|---|
| Интернет и ключ | Не нужны | Нужны выбранный режим, модель, API-ключ и доступ к сети |
| Сигнатура файла | Проверяется до классификации; конфликт с расширением отправляет файл в Review | Не может заменить сигнатуру и не выбирает путь |
| Исходный код | Синтаксические признаки C#, Python, Java, JavaScript/TypeScript, SQL, C, C++, HTML и CSS | Может уточнить смысл доступного текста и предложить категорию из справочника |
| Учебные/рабочие/финансовые документы | Ключевые слова и сохранённое точное правило имени | Семантическая интерпретация ограниченного извлечённого текста |
| Изображения, аудио и видео | Категория определяется по сигнатуре; приложение извлекает ограниченные технические метаданные и локальный OCR | Для PNG/JPEG/WebP с отдельным разрешением провайдер анализирует изображение и выбирает фото, скриншот, скан, схему, иллюстрацию или прочее; транскрибации аудио/видео нет |
| Приватность | Текст остаётся на устройстве | До 24 000 символов извлечённого текста может быть отправлено выбранному провайдеру |
| Поведение при сбое | Продолжает работать | Ошибка провайдера оставляет локальный результат и объяснение; Compare с неполным ответом уходит в Review |
| Воспроизводимость | Правила версионированы в исходном коде, правила пользователя — в локальной базе | Результат зависит от выбранной модели и провайдера |

## Решение локального классификатора

1. Конфликт расширения с содержимым или подозрительная структура ZIP останавливают обычную классификацию.
2. Сигнатуры EXE, изображений, аудио, видео и архивов дают типовую категорию без попытки интерпретировать бинарные данные.
3. Текст и код ограниченно извлекаются, затем проверяются синтаксические регулярные признаки.
4. Для текста и документов применяются ключевые слова учёбы, работы и финансов.
5. Если пользователь явно подтвердил категорию и отметил сохранение правила, точное совпадение нормализованного имени получает приоритет для последующих текстовых документов с тем же именем.

Оценка уверенности — эвристика приложения, а не статистически калиброванная вероятность. Например, сигнатура формата может дать значение около `0.93–0.96`, документные ключевые слова — около `0.88–0.90`, а обычный текст без темы — `0.68`. Эти числа нужны для порогов маршрутизации и не являются гарантией точности.

## Облачный анализ

Режим `Off` используется по умолчанию. В `Auto` настроенные провайдеры вызываются по очереди. В `OpenAI`, `Gemini` и `Claude` выбранный адаптер используется отдельно. `Compare` отправляет один и тот же prompt двум настроенным провайдерам параллельно:

- совпали категория и подкатегория — сохраняется общий результат и среднее значение уверенности;
- ответы расходятся — уверенность ограничивается уровнем ручной проверки;
- ответил только один провайдер — результат помечается как неполное сравнение и отправляется в Review.

Все ответы проходят одну проверку: JSON Schema без лишних полей, валидные ID справочника, ограничение полей и диапазон уверенности `0..1`. Свободный путь назначения и новое расширение от модели не применяются автоматически.

В запрос включаются расширение, MIME, определённый формат, размер, локальная гипотеза и ограниченный извлечённый текст/технические метаданные. Перед вызовом проверяются разрешённый тип файла и список локальных приватных папок. Имя файла и локальный полный путь в prompt не отправляются. Байты изображения передаются только при отдельном разрешении, для PNG/JPEG/WebP, до 12 МБ и если формат включён в allowlist. При включённом визуальном анализе он запускается автоматически для подходящих изображений; отказ, отсутствие ключа, превышение размера или секрет в OCR не мешают локальной обработке.

## Фильтр вероятных секретов

До облачного вызова локальный фильтр ищет приватные ключи, распространённые токены, значения вида `password`, `api_key`, `secret` и `.env`-имена. При срабатывании файл остаётся на локальном конвейере. Это эвристический фильтр, не универсальное обнаружение персональных данных; пользователь сам выбирает, включать ли облачный режим.

## Как сравнить результаты на демонстрационном наборе

Набор примеров находится в `demo/samples/`. Для каждого файла можно записать результат в таблицу:

| Файл | Ожидаемая категория | Локальная категория/статус | ИИ категория/статус | Комментарий |
|---|---|---|---|---|
| `Батыр` | Programming / C# | заполнить при показе | заполнить при показе | C# без расширения |
| `Задание-практика.txt` | Documents / Study | заполнить при показе | заполнить при показе | тема выражена словами |
| `Нейтральная-заметка.txt` | Review / Other | заполнить при показе | заполнить при показе | мало контекста |
| `Поддельное-изображение.jpg` | Review | заполнить при показе | не вызывается до решения о формате | валидный пустой ZIP с расширением JPG |

Таблица выше описывает ожидаемое поведение, а не результаты измеренного прогона. Точные показатели качества нельзя утверждать без запуска на конкретных документах и настроенном аккаунте провайдера.
